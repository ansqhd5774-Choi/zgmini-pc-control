# ZGMINI — 공통 승인 패키지 조회·적용 계약 R1

상태: 설계 및 독립 테스트 단계. 이 문서와 소스 병합은 실제 Windows 수신기 설치/운영 사용 승인 증거가 아니다.

## 목적 및 범위

새 콘텐츠마다 Controller에 기능별 조회기와 CMD 설치기를 추가하는 반복을 없앤다. 고용 R6, 물가지표, 테마 공포탐욕 등 기존 성공·차단 사례를 동일한 작업 종류로 분류한다. 기존 `pc-job` 7필드 요청, source-only Writer B, Provider Flags B, Controller 자체 유지보수기 계약은 유지하며 다른 등급·범위로 우회하지 않는다.

## 작업 유형

1. `approved-preimage-readonly`: 고정 승인 프로필의 설치 상태·허용 파일 SHA-256·크기·존재 여부, 기존 Task XML SHA/활성 상태/고정 실행 포인터, 백업·lock 존재 여부만 출력. A/light, 파일 본문·명령행·키·환경변수·원자료 출력 없음.
2. `approved-versioned-bundle-stage`: source SHA와 모든 상대경로/바이트 SHA/크기가 고정된 패키지를 승인 프로필의 `versions/<digest>`에 불변 설치. `.mjs`·`.json`·`.md` 등 데이터/소스 파일을 명시적 파일 목록으로 검산. 임의 manifest source 코드 실행 금지.
3. `approved-launcher-activate`: 허용된 기존 `.cmd`/`.vbs` 진입점 및 `ACTIVE_RUNTIME.json`의 정확한 이전/목표 SHA를 확인하고, 단일 공유 lock·원본 ACL 보존 백업·교체·readback·실패 복구. 기존 Task XML 자체 변경, 새 예약, DB/D1/원자료/환경변수 변경 금지.
4. 기존 `pc-writer-source-install`과 `provider-flags-b`는 별도 계약으로 계속 지원. 이번 패키지 실행기는 이들을 대체하거나 내부 우회하지 않음.

## 동적 등록의 신뢰 경계

- 런타임의 임의 Issue JSON은 PC 경로·파일 목록·명령을 지정할 수 없다. 허용 `operation`만 요청 가능하다.
- 공통 수신기는 *별도 승인된 manifest 바이트 SHA*와 기존 인증된 계정/브랜치/커밋/신규 요청 ID를 교차 검증한다.
- 신규 콘텐츠는 승인된 프로필·manifest로 등록한다. 프로필은 고정 루트/작업 유형/허용 파일 범위/최대 개수/최대 크기/Task 불변 보호 계약을 포함한다. 재사용 가능한 작업 유형을 추가할 때에만 공용 실행기 소스 갱신을 검토한다.
- 경로 역행 `..`, 절대경로, 드라이브 접두, UNC, 심볼릭 링크/reparse point, 대소문자 무시 중복, Windows 예약 이름/후행 공백·점, 과도한 크기는 입력 단계에서 거부한다.
- A급은 원문·민감값을 외부 반환하지 않는다. 결과는 기존 32KiB 한도를 준수하고, 필요 시 승인 프로필 단위로 나누어 요약한다.

## 안전한 단회 적용 순서

1. **사전검증**: 승인 manifest 해시·프로필·source SHA·Task XML/현재 런처 SHA·시스템/기능 lock·현재 버전 기록 및 실제 설치 원본 확인.
2. **준비**: 겹치는 Writer 자원만 직렬화, 새 고유 requestId로 공유 잠금 획득, 동일 ACL의 원본 백업과 fsync, 동일 드라이브 격리 stage에 불변 패키지 검산.
3. **전환**: 최종 CAS 및 Task drift 재검사 후 허용 진입점/활성 기록만 원자 교체. 실행기/프로세스/Task 자체는 무단 재시작·변경 금지.
4. **검산**: 설치 파일의 목표 해시, 런처·버전 메타데이터, Task XML/상태, 보호 상태/기존 데이터 불변 확인. PC 원장/결과 JSON·TXT 2/2 업로드와 GET 재조회.
5. **오류**: 마지막 변경 단계와 보호 상태를 코드로 보고. 원본 백업에 의해 정확한 복원이 입증되면 STOP_RESTORED, 부작용 불명확하면 RECOVERY_REQUIRED. 기존 ID 자동 재실행 금지.

## 검증 기준

- 정상: A 조회·고정 bundle stage·런처 활성 후 실제 PC readback; A 조회/자료 변경 0, 새 Task 0, 운영 Core 불변.
- 안전 실패: 불일치 old SHA, 누락/중복 파일, 잘못된 경로, 심볼릭 링크, 변조 manifest, Task drift, 잠금 경합, 부분 전환, 결과 업로드 실패 모두 각각 확인 가능한 결과 코드.
- 회귀: 이전 Writer B·Provider Flags B·고용 A·물가지표 A 및 다른 독립 조회에 회귀 없음.
- 확장성: 같은 작업 유형의 두 번째 신규 콘텐츠가 **공통 실행기 코드 변경 없이** 승인 프로필/manifest 등록만으로 조회·설치 가능한지 모의 시험.

## 담당 분리

- 프로세스 총괄: 공통 실행 유형·수신기·계약·안전 테스트·실PC 설치 검증과 공유 조정.
- 기능 원담당: 패키지/source/manifest의 기능 내용·기존 승인 효과·정규 B 요청/결과 회수·수집→저장→계산→게시→UI 검증.
- 공용 경로가 미등록이어도 독립 개발·테스트는 계속하며 사용자 수동 `RUN_PREFLIGHT.cmd`를 기본 선택지로 제안하지 않는다.
