# 일반챗 작업 전 공통 지침

아래 본문을 작업 시작 전 전달한다. 이 문서는 요약 진입점이며 과거 SHA·PID·설치 상태를 고정하지 않는다.

---

현재 업무·브랜치·기존 승인·완료 증거를 보존하고 이어서 수행하라.

1. `ansqhd5774-Choi/zgmini-pc-control` main의 `AGENTS.md`, `docs/GENERAL_CHAT_START.md`, `docs/PC_AUTOMATION_STANDARD.md`를 읽어라. 공유 적용은 #68, 설치 장애는 `docs/CONTROLLER_RECOVERY.md`를 따른다. 오래된 사본보다 최신 정본과 실제 Runtime 증거를 사용하라.
2. 대상 업무에 필요한 실제 설치 모듈·입력·승인 범위만 확인하라. 공통 필수 등록·설치·검증 상시 승인은 기능 구분 없이 재사용하고 같은 범위의 재승인을 요구하지 마라. 본 업무의 게시·배포 효과는 기존 업무 승인을 확인하라.
3. 현재 상태는 설치 SHA·활성 lease·fresh heartbeat·실제 결과로 판단하라. 지원되는 PC 수단으로 `tools/automation-status.mjs`를 조회할 수 있으면 그 읽기 전용 결과를 사용하라. 도구가 설치된 일반 pc-job에 있다고 가정하거나 임의 shell로 우회하지 마라. 조회 snapshot은 관측시각과 유효기간을 확인하고 과거 실패 원장을 활성 장애로 단정하지 마라.
4. 요청 전 schema·고유 ID·정확한 source·manifest를 검증하고 한 번 제출하라. 요청 생성 전 거부, 생성 응답 불명확, 접수 대기, PC 실행 실패, 결과 업로드 실패를 구분하라. 도구 안전 검사 거부 시 원문 사유와 차단 행동을 비민감하게 기록하고 다른 도구로 같은 차단 행동을 우회하지 마라. 응답 유실이면 기존 요청부터 조회하라.
5. 설치 장애는 기존 요청/담당을 유지해 원장·실제 파일·소유자·부분 적용을 확인하고 지원되는 복구 경로를 사용하라. 기존 복구가 완료됐다면 증거를 재사용하고 중복 복구하지 마라. 무부작용 취소·rollback·실제 갱신 PASS를 구분하라.

   원장 없는 UNKNOWN은 `docs/INSTALL_FAILURE_120_20261103.md`의 검증된 오류 전달·무변경 preflight 경로를 참조하라. 현재 설치 source의 지원 여부를 먼저 확인하라. Supervisor heartbeat·GitHub Online만으로 6개 관리 좌석을 증명하지 마라. 설치 #123·사후 진단 #124와 `results/INSTALL_FAILURE_120_REPAIR_20261103.json`의 실제 성공 증거는 해당 범위에서 재사용하라. ER1 모듈 설치를 과거 R17 대기나 #106 복구로 되돌리지 마라. 이후 업무별 게시·배포는 별도 단계다.

   공통 예방 코드의 설치 증거는 `results/COMMON_MAINTENANCE_HARDENING_20261103.json`에 있다. 과거 구버전 제한을 최신 유지보수기 제한으로 단정하지 말고 실제 설치 source와 프로필을 대조하라. 기능별 heavy 예외를 새로 만들지 말고 검증된 공통 자원 프로필과 정확한 승인 명세를 사용하라.
6. 독립 작업은 계속하고 공유 설치·쓰기는 자원별로 직렬화하라. 새 진단이나 설정 추가가 공통 기반 교체를 꼭 요구하는지 기존 adapter부터 확인하라. 문서·명세로 처리 가능한 작업을 임시 실행기·예약 복제로 늘리지 마라.

   특정 담당자의 도구 거부를 전체 설치 실행 중으로 간주하지 마라. 필요한 모듈·산출물·경합 자원으로만 선행 조건을 설명하고 #68 본문과 최신 결정을 맞춰라. 담당 변경으로 거부된 동일 행동을 우회 제출하지 마라.
7. 대기 보고에는 현재 단계·정확한 원인·담당·지원 도구·다음 실행·해제 조건을 명시하라. 근거 없는 BLOCKER, 완료율, 과거 실패의 반복 보고를 하지 마라. 구현/설치/실행/게시/공개를 구분하고 결과 TXT·JSON·댓글을 직접 회수하라.
8. 승인된 업무의 manifest·해시·누적 diff·실행 명세·검증 자료는 현재 담당자가 완성하고 다음 단계까지 진행하라. 미작성 자료·브랜치 분기·과거 대기 보고만으로 멈추지 마라. 공용 담당이 없고 실제 경합도 없으면 #68에 등록하고 조정을 맡되, 기존 담당은 명시적 인계로 변경하라. 실제 접근 거부·활성 자원 충돌·승인 범위 밖 결정·검증 실패가 있을 때만 영향을 받는 단계의 증거와 해결 행동을 보고하라. 안전 검사를 우회하지 마라.

핵심은 현재 실행과 원본 증거를 기준으로 다음 지원 동작까지 수행하는 것이다. 지침을 읽었다는 보고만 하고 멈추거나 완료 작업을 처음부터 재시작하지 마라.
