# 일반챗 작업 전 공통 지침

**CI 19개 실제 사용(2026-11-26):** 소스·Workflow·데이터·브라우저 변경은 [R1 8영역 + R2 11기술 사용 기준](PC_AUTOMATION_STANDARD.md#ci-19개-공통-사용-계약--2026-11-26-사용자-확정)에서 영향받는 기존 검사만 선택하고 정확 HEAD 실행 증거·누락 트리거를 확인한다. 적용 불가/N/A 이유를 남기며, 기존 유효 성공은 재사용한다. R2 #8 웹 Good/P75는 제외(삭제), #24 격리 성능 CI는 유지. 19개 전부를 매번 실행하는 새 Gate, 예약/유료 서비스/운영 승인 확대는 금지한다.

**Cloudflare 공식 조회(2026-11-24):** Cloudflare 활성 배포·트래픽·Version·도메인 검증은 웹 디버그나 사용자 수동 조작 대신, 이미 운영 PC에 설치돼 실제 [#3306 PASS](https://github.com/ansqhd5774-Choi/zgmini-pc-control/issues/3306)한 허용 A급 `w05-cloudflare-deployment-readonly`와 기존 Wrangler OAuth의 고정 공식 GET을 1차 경로로 사용한다. 먼저 유효한 JSON/TXT 결과를 재사용하며, 필요한 새 읽기만 고유 `pc-job`으로 단회 실행·회수한다. [표준 절차](CLOUDFLARE_OFFICIAL_PC_READONLY_STANDARD.md). 읽기 성공을 Cloudflare 배포·DNS·D1 쓰기 승인이나 Git source SHA 독립 attestation으로 확대하지 않는다.

**Controller 요청 누락 방지(2026-11-23):** [기존 단회 제출 도구](CONTROLLER_AUTO_UPDATE.md)의 생성·제출·원본 readback을 사용한다. 제목/라벨을 수동으로 따로 붙이지 않는다. 응답 불명은 기존 영수증 `reconcile`로 조회하며 재제출하지 않는다. 이 도구는 승인이나 설치 완료를 대신하지 않는다.

**2026-11-22 반복 정체 방지:** 도구 접근 실패를 기능 장애로 확대하지 않는다. 원래 요청의 최신 결과·원장 단계를 먼저 확인하고, 승인 명세의 정확한 소스와 이동하는 main 끝을 구분한다. 기존 승인 효과는 실행 명세에 연결해 진행하고 실제 부족한 효과만 결정받는다. 독립 작업은 계속한다. [공통 정본의 승인·실행·결과 연결 기준](PC_AUTOMATION_STANDARD.md#승인실행결과-연결의-반복-정체-방지--2026-11-22)을 따른다.

**2026-11-21 정상본 복귀 우선:** 모든 승인된 변경 작업은 기존 manifest/journal에 해당 범위의 이전 정상 상태·복귀 방법·복귀 확인을 포함한다. 확정 실패 시 운영 복구를 원인 분석보다 우선하고, 검증된 정상본 복귀 후 기존 승인 업무를 계속한다. Controller/Writer뿐 아니라 배포·DB·게시에도 효과별 복원/보상 범위를 적용하되 읽기 전용에는 불필요한 롤백을 요구하지 않는다. 결과 불명·동시 변경은 실제 상태/CAS를 확인하며 임의 덮어쓰기·재실행을 하지 않는다. 새 승인·전역 Gate·예약 감시를 추가하는 지침이 아니다. [공통 실행 기준](ROLLBACK_FIRST_WORKFLOW.md).

2026-11-19 자동 장애 인계·증거 기반 분석 통합 개정. [전체 정본](PC_AUTOMATION_STANDARD.md)이 기준이며 이전 지침의 과거 사건/승인 보류를 현재 작업의 전역 조건으로 적용하지 않는다.

**승인된 작업은 진행이 기본이다.** 현재 행동의 데이터 손상·권한 초과·중복 효과·실제 충돌과 관계없는 조건을 새로 붙이지 않는다. 조회·준비·격리 시험에 운영 설치/게시 승인이나 전체 정상 증명을 요구하지 않는다. 이미 승인된 범위의 명세·해시는 담당자가 완성하며, 무관한 과거 실패·인계 상태·자료 미작성을 사용자 재승인 사유로 삼지 않는다. 직접 위험이 있는 행동만 보류하고 나머지는 계속한다.

**조회·출력·인계:** 커넥터는 유지하고 현재 대상 검색→관련 함수/변경/실패 구간→필요한 의존성 순으로 조회를 확장한다. 필드 선택·필터를 반환 전에 적용하고 전체 코드·원장·로그·도구 목록의 반복 출력을 줄인다. 원본 위치/SHA/시각을 보존하며 출력 잘림·요약을 전체 확인으로 오판하지 않는다. 중요한 승인·설치 직전 상태는 실제 원본과 대조한다. 새 대화에는 목표·승인/제외·완료 증거·진행 중 요청/체크포인트·미해결/다음 행동을 인계하고 중복 실행하지 않는다. 고정 파일 수·매번 새 대화·커넥터 해제·새 승인 Gate는 요구하지 않는다.

**문제 해결 방식:** 오류명을 원인으로 취급하지 말고 실제 실패 조건과 입력을 대조한다. 함께 막힌 대상을 분해하고 비교 기준을 확인한 뒤, 원인 가설을 구분할 증거를 기존 코드·기록에서 먼저 찾는다. 증거로 원인을 좁혀 최소 수정하고 실제 실패 경로에서 검증한다. 같은 집계·설치·보고의 반복을 진전으로 삼지 않는다. 원인이 이미 입증됐으면 추가 조사 없이 실행한다. [전체 정본](PC_AUTOMATION_STANDARD.md)의 ‘증거 기반·가설 검증형 문제 해결’을 적용하며 새 승인·필수 서류는 추가하지 않는다.

**자동화 사용:** 기존 PC/Writer 실패 접수·인계 라우팅·후보 선정·관제·R1 능동 진단·R2 정적 증거 비교·R3 범위 탐색을 재사용한다. 활성 변수·workflow·실제 Run·사건 접수·담당 인수·운영 해결을 구분한다. 봇 ACK/후보/정적 진단은 실제 수리·타 대화 수신이 아니다. 이미 인수한 승인 작업은 자동 처리 대기로 돌리지 않는다. 결과는 자기 원본 Issue/requestId의 JSON/TXT와 영수증으로 회수하며, 보조 원장의 일부 실패·포화를 모든 업무의 Gate로 확대하지 않는다. 상세는 [전체 정본](PC_AUTOMATION_STANDARD.md)의 자동화 절을 따른다. 새 예약·Runner·승인 단계는 추가하지 않는다.

업무 데이터 쓰기 금지와 정상 조회에 필요한 잠금·SQLite 보조 상태를 구분한다. 승인된 고정 조회는 native 읽기 전용 트랜잭션으로 진행하며, 원본의 모든 바이트 동결이나 WAL 보조 파일의 특정 조합을 일괄 선행조건으로 삼지 않는다. 임의 보조 파일 삭제·강제 checkpoint·운영 DB immutable/nolock 우회는 하지 않는다.

1. 현재 업무의 목적·승인·브랜치·마지막 유효 완료 증거와 다음 실행 하나를 계승한다. 신규 대화에만 AGENTS/시작 문서/정본의 관련 범위를 읽는다.
2. 운영 PC와 격리 PC, remote source·설치 Controller·운영 HEAD/config.source·검사 source를 구분한다.
3. 작업의 실제 효과(고정 읽기/격리 계산/공급자 수집/설치/게시/복구)에 필요한 조건만 적용한다. 파일 해시 조회에 활성 Core 전체 계보나 과거 취소 로그를 불필요하게 요구하지 않는다.
4. 설치된 schema/허용목록·고유 요청/승인 manifest·원본 해시를 사용한다. 임의 명령·SQL·원격 스크립트로 우회하지 않는다. 기존 성공 구조를 재사용하고 재설치·중복 시험을 하지 않는다.
5. 결과 불명확은 기존 실제 상태부터 대조한다. 종료된 무변경 A 조회는 현재 정상 경로와 같은 승인 scope를 확인해 새 ID 한 번으로 재개할 수 있다. 쓰기·공급자 호출·활성/불명 lease는 별도 검증한다.
6. Writer B 자연 유휴가 반복 실패하면 승인된 유지보수 모드(원본 Task SHA 고정·신규 시작 억제·정상 drain·CAS 설치·원본 복원)를 쓴다. 강제 종료·lock 삭제·같은 ID replay는 하지 않는다. 실제 선례 #2234→#2235→#2236.
7. 인계 후보는 실행이 아니다. 실제 인수 시 기존 ACKNOWLEDGED→WORKING을 기록하고 지원 행동과 원본 회신까지 수행한다. 코드 없는 진단은 실제 PC Issue/JSON/TXT로 반환하며 PR을 억지로 만들지 않는다. 자동 AI/다른 대화 수신은 실증 전 미검증이다.
8. 구현/CI/병합/설치/Runtime/게시/자연 갱신을 구분한다. 실제 결과와 사후 확인까지 완료하고 현재 업무를 막지 않는 문제는 별도로 남긴다.
9. 동일 승인 범위는 재승인 없이 진행한다. 현재 요청 밖 운영 효과·관리자/보안 변경만 별도 판단한다. 비밀정보·원자료·다른 작업자 변경을 보호한다.
10. 최종 보고는 결과·실제 증거·중요한 남은 범위·다음 행동만 한국어로 짧게 작성한다.
