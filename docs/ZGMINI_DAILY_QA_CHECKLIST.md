# ZGMINI 일일 품질 점검표 (Daily QA Checklist)

- 문서 버전: DAILY-R1 / 2026-11-05 KST

- 기준: [총괄 QA-R7](./ZGMINI_MASTER_QA_STANDARD.md) · 적용 브랜치 `codex/zgmini-quality-audit-20261105`
- 목적: **이미 발표·제공된 최신 데이터의 누락 탐지·조치 우선**, 공개 화면 정상 표시, 공통 상세 양식 회귀, 불필요한 실행 차단 발견
- 상태: **사용 전 점검표 템플릿 / 실제 일일 점검·예약 실행은 미수행·미등록**. 새 수집기·예약·운영 쓰기·배포에 대한 승인 문서가 아니다.
- 범위: 현재 실제로 공개되는 URL 및 지표·세부 시계열 **전체**. 소스 `public/sitemap.xml`의 36개 URL(메인 1, 위험지표 목록·상세 9, 경제지표 목록·상세 13, 별도 동적 6, 정적/가이드 7)은 조사 당시 **출발점**이며 운영·세부 시계열 완전성을 보장하지 않는다.
- 수행 방식: 매일 **경량 메타데이터 전수(Q03)** + 변경·오류 항목 깊이 검증 + 대표 PC·모바일 화면. 아래 11개 검사를 **하나의 점검 회차**로 수행한다. 기존 정당한 성공 증거는 재사용한다.

## 1. 이번 회차 입력과 진행률

| 필드 | 기록값 |
| --- | --- |
| 점검일·기준 시각(KST) / 점검 ID | YYYY-MM-DD / HH:mm / QA-YYYYMMDD-01 |
| 실제 서비스 도메인·대상 URL 등록부 버전 | 확인된 URL / 등록부 기준 SHA 또는 갱신 시각 |
| 사용한 정본 QA 문서 SHA / 개발 main SHA | 확인값 또는 `NOT_RUN` |
| 운영 실행/배포 SHA | 이번 문제와 관련될 때만 확인; 개발 main과 혼동 금지 |
| 전일 마지막 유효 결과·미해결 건 | 링크·실측 시각 / 새 결과와 구분 |
| 전체 동적 세부 시계열·검사 완료·누락·미검증 | 등록 N / 판정 n / 누락 n / 미검증 n |
| 일일 필수 검사 진행률 | 시작 0/11 (0%) → 종료 실측 판정 건수/11 (%) |
| 정상률 / 수집 연결 건강 | **별도 수치**(확인된 정상 수/실제 확인 수, 연결 건강 근거) |
| 검사자/책임자 | 이름 또는 담당 경로 |

**진행률 규칙:** 분모는 당일 11개 필수 검사. 실제 근거로 `PASS` 또는 `FAIL` 판정한 항목만 완료 수에 넣는다. `PARTIAL`, `STATE_UNKNOWN`, `NOT_RUN`, `AUTOMATION_BLOCKED`는 완료·정상으로 합산하지 않는다. 조건부 검사는 발동 여부와 완료율을 별도 기록한다. 하나의 세부 시계열이라도 공식 자료 미반영 `FAIL`이면 **전체 최신성 PASS 금지**.

**일일 보고서 필수 판정 규칙(모든 회차 적용):** 결과 열에는 **`합격` / `불합격` / `미검증`만** 기입한다. `합격`은 해당 대상의 기준 충족을 실제 증거로 확인한 경우, `불합격`은 실제 측정·운영 증거로 위반을 확인한 경우에만 사용한다. `PARTIAL`·`NOT_RUN`·`STATE_UNKNOWN`·`AUTOMATION_BLOCKED`·결과 불명은 **`미검증`**으로 기록하되 내부 진단 코드는 메모에 남긴다. 확인된 부분의 `FAIL`은 별도 세부 행으로 분리한다. **근거가 없다는 이유만으로 불합격을 기록하는 행위는 금지한다.** 미검증은 합격·불합격 양쪽 집계에서 제외하지만 필수 검사 완료에도 넣지 않는다. **데이터/서비스 판정**과 **QA 수행 완료 판정**을 별도 표시하여 점검 미완료를 사이트 장애로 보고하지 않는다.

### D03 문제 발견 시 최우선 진단 흐름

1. 공식 발표·공급처 신규 관측값이 **실제 제공**됐는가? 발표 지연·휴장·시간대가 근거 있으면 그 상태로 분리.
2. 승인된 수집 기회 후 PC에 신규 관측일·원자료가 있는가? 없으면 **수집 단계** 문제.
3. PC 원자료는 있는데 계산 결과가 없거나 오래됐는가? **계산 단계** 문제.
4. PC 결과는 최신인데 게시/D1/API가 오래됐는가? **게시 단계** 문제.
5. D1/API는 최신인데 상세페이지의 값·날짜·판단·차트가 다르면 **Reader/UI 단계** 문제.

**원칙:** 이미 발표·제공됐으나 공개 화면에 빠진 항목은 신규 미래 수집 계획보다 **먼저 문제를 특정하고 담당자에게 복구·재검증**한다. QA가 별도 승인 없이 수집·수정·게시·배포를 실행하지 않는다. 앞단이 검증되지 않았는데 뒷단까지 정상으로 단정하지 않는다.

| 접근 제한·quota·상태 미확정 | 해당 검사만 `AUTOMATION_BLOCKED`/`STATE_UNKNOWN`. 미승인 우회·자동 재시도 금지. 다른 독립 점검은 계속 |
